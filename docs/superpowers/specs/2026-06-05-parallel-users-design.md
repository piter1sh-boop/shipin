# 并行用户系统设计规格

> **创建日期:** 2026-06-05
> **版本:** v1.0
> **目标:** 真实用户 + AI用户并行运作，AI用户作为深度测试资产

---

## 1. 概述

### 1.1 核心概念

并行用户系统让真实用户和AI用户在同一个平台上并行运作：
- **真实用户**通过邮箱注册登录，使用系统完成30天创业验证
- **AI用户**由管理员创建，系统驱动执行，自动与AI教练对话
- 两者数据隔离但都服务于系统进化

### 1.2 解决的问题

1. 在没有真实用户的情况下快速验证系统闭环
2. AI用户可进化成有完整创业能力的数字实体
3. 真实用户数据持续优化AI教练的个性化能力

---

## 2. 用户类型

### 2.1 三种用户角色

| 角色 | 认证方式 | 数据可见性 |
|------|----------|------------|
| **真实用户** | 邮箱 + 密码注册登录 | 仅自己和管理员可见 |
| **AI用户** | 系统生成账号，系统驱动 | 仅管理员可见 |
| **管理员** | 独立管理员账号 | 可查看所有用户和AI用户画像 |

### 2.2 真实用户

- 通过邮箱+密码注册
- 拥有完整的30天创业教练体验
- 画像由系统从行为数据中自动学习更新
- 可查看自己的Dashboard、任务、教练对话、进度

### 2.3 AI用户

- 由管理员创建（2步：选创业领域 + 当前阶段）
- 系统生成完整虚拟画像（姓名、年龄、职业、性格、思维习惯、技能等）
- 由Agent引擎驱动执行任务
- 日常任务自动完成，遇卡点时与AI教练对话
- 画像随执行数据持续进化
- 是系统的重要数字资产

---

## 3. AI用户虚拟画像生成

### 3.1 管理员创建流程（2步）

**Step 1:** 选择创业领域
- AI开发者 / 电商 / SaaS / 内容创作 / 本地服务 / 工具类

**Step 2:** 选择当前阶段
- 定位 / 验证 / MVP / 销售 / 复盘

**Step 3:** 点击创建

### 3.2 系统生成内容

管理员选择后，系统自动生成：

**基本信息：**
- 姓名（随机生成中文名）
- 年龄（25-45岁）
- 职业背景（与领域相关）
- 学历（大专/本科/硕士）
- 所在城市

**创业背景：**
- 为什么创业（放弃的工作/机会成本）
- 预期30天收获
- 最大的担忧

**性格特征：**
- 外向/内向倾向
- 执行力评分（1-10）
- 决策风格（果断/犹豫/分析 paralysis）
- 压力应对方式

**思维习惯：**
- 分析问题的方式
- 遇到困难的第一反应
- 学习风格

**技能雷达：**
- 技术能力（1-10）
- 产品能力（1-10）
- 销售能力（1-10）
- 运营能力（1-10）

**卡点预测：**
- 最容易卡在哪个环节
- 典型逃避行为
- 需要什么样的推动

**30天目标：**
- 产品方向
- 目标用户
- 核心假设

## 4. AI用户Agent执行引擎

### 4.1 执行模式：混合模式

**日常任务模式：**
- Agent按计划自动完成任务
- 生成模拟访谈记录（基于虚拟画像的回复）
- 完成每日check-in
- 更新任务状态
- 数据写入数据库

**卡点触发：**
- 当任务失败率超过阈值或连续跳过时
- 自动切换到对话模式
- 与AI教练对话寻求建议
- 根据建议调整执行策略

### 4.2 Agent工作流

```
1. 读取今日任务
2. 检查任务完成条件
3. 执行任务（模拟行为）
   - 成功 → 写数据库，更新状态
   - 失败 → 检查连续失败次数
4. 如果连续失败N次 → 触发AI教练对话
5. 根据教练建议调整
6. 更新画像数据
7. 进入下一个任务
```

### 4.3 模拟真实性

Agent模拟真实用户行为：
- 不会100%完成任务，总有1-2个跳过
- 有固定的卡点类型（根据画像）
- 与教练对话时表现符合性格设定
- 任务完成率在0.5-0.8之间波动

## 5. 认证系统

### 5.1 真实用户注册登录

**注册：**
- 邮箱（唯一）
- 密码（最少8位）
- 注册后发送验证邮件（可选）

**登录：**
- 邮箱 + 密码
- JWT token（7天过期）
- Refresh token（30天）

**数据隔离：**
- 每个用户只有自己的数据
- 路由守卫：未登录重定向到登录页

### 5.2 管理员账号

- 独立于普通用户
- 管理员账号在系统初始化时创建
- 可通过环境变量配置

### 5.3 AI用户账号

- 系统生成，不可登录
- 由Agent引擎代为操作
- 有独立的userId和数据空间

## 6. 管理后台

### 6.1 用户管理

**用户列表：**
- 显示所有真实用户和AI用户
- 筛选：真实用户 / AI用户 / 所有
- 显示：阶段、任务完成率、访谈数、线索数

**用户详情：**

真实用户：
- 基本信息
- 行为数据
- 画像摘要
- 最近活动

AI用户：
- 完整虚拟画像
- Agent执行日志
- 进化历史
- 当前状态

### 6.2 AI用户创建

**步骤1：** 选择创业领域（下拉选择）

**步骤2：** 选择当前阶段（单选）

**步骤3：** 点击创建 → 系统生成画像 → 显示预览

**步骤4：** 确认创建或重新生成

### 6.3 AI用户执行监控

- 当前执行到第几天
- 今日任务状态
- 最近卡点（触发对话的记录）
- 画像更新历史

## 7. 数据模型

### 7.1 新增表

**users**
```sql
- id (PK)
- email (唯一，真实用户)
- password_hash
- role (user/admin/ai)
- is_ai_user (boolean)
- ai_profile_id (FK，可选)
- created_at
- updated_at
```

**ai_profiles**
```sql
- id (PK)
- user_id (FK -> users)
- name
- age
- occupation
- education
- city
- personality (JSON)
- skills (JSON)
- background (JSON)
- thinking_habits (JSON)
- predicted_blockers (JSON)
- goals_30days (JSON)
- created_at
- updated_at
```

**ai_agent_logs**
```sql
- id (PK)
- ai_user_id (FK -> users)
- action_type (task_complete/skip/checkin/coach_chat)
- details (JSON)
- created_at
```

### 7.2 修改现有表

**users表**
- 新增 is_ai_user 字段
- 已有 users 表结构兼容

## 8. API设计

### 8.1 认证API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/auth/register | 注册 |
| POST | /api/auth/login | 登录 |
| POST | /api/auth/logout | 登出 |
| GET | /api/auth/me | 获取当前用户 |

### 8.2 管理API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/admin/ai-users | 创建AI用户 |
| GET | /api/admin/users | 获取所有用户（含筛选） |
| GET | /api/admin/users/:id | 获取用户详情 |
| GET | /api/admin/ai-users/:id/profile | 获取AI用户画像 |
| POST | /api/admin/ai-users/:id/start | 启动AI用户执行 |
| POST | /api/admin/ai-users/:id/stop | 停止AI用户执行 |

## 9. 技术实现

### 9.1 技术栈

- **认证：** JWT + bcrypt
- **数据库：** SQLite（已有），新增表
- **AI用户执行：** Node.js定时任务 + AI教练API调用
- **管理后台：** 扩展现有Admin页面

```
server/
```
